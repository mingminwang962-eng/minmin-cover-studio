# 内容资料库：直接保存到当前内容文件夹

命令由助手执行，用户不用操作终端。脚本路径以当前 Skill 的 `scripts/asset_library.py` 为准，需要 Python 3 与 Pillow。以下用相对脚本路径演示；从其他工作目录运行时改成绝对路径。

## 自动使用当前内容文件夹

不询问用户保存位置，不显示首次设置问卷或文件夹选择器。助手从上下文确定本次内容目录：优先使用正在制作的选题／文章／视频期次文件夹；尚无单独内容文件夹时，使用当前任务所属项目目录。路径从内容文件、当前项目上下文或已知轮次确定，不把执行脚本所在的 Skill 目录、附件临时目录或其他内容的目录当作当前内容目录。用户不用填路径或运行命令。

所有命令由助手传入 `--content-dir "/当前内容文件夹"`，即使命令执行工作目录不同也仍写入该内容目录。`photos` 和 `prepare` 在首次调用时自动建库；之后复用该内容目录内的 `.cover-studio-profile.json` 与“我的封面工作室”。不自动读取 `~/.config/cover-studio/profile.json`，不因过去做过另一个内容而串库。

`status` 只检查现有库，浏览不会创建空库。照片与封面可直接开始保存，无需先执行 `init`：

```sh
python3 scripts/asset_library.py --content-dir "/当前内容文件夹" photos "/本次附件/照片.jpg"
```

成功后生成：

```text
当前内容文件夹/我的封面工作室/
  .cover-studio.json          资料库身份标记
  照片集/
    原照片/                  原始文件，按内容哈希命名
    照片索引.json             稳定编号、原名、上传批次、来源和哈希
    照片墙.html
  封面作品/{本轮}/
    config.json、batch.json、plan.json、prompts/、候选/、风格墙.html
    已保存/{版本编号}/        图片、提示词和生成记录的留存副本
  封面索引.json
  我的封面墙.html
```

每次使用本次内容目录下的配置，不重复创建、不混入其他内容。内容目录不可用、资料库身份不符或无写权限时说明具体失败并保留待保存源文件，不能回退到其他目录。历史全局配置与旧库保留原位；仅维护明确指定的历史库时可显式传 `--profile`，新内容不使用该兼容入口。

## 每次上传照片

从本次附件取得实际可读的文件路径。每次接收用于此封面流程的用户照片（包括只补充照片、不生图），都执行：

```sh
python3 scripts/asset_library.py --content-dir "/当前内容文件夹" photos "/本次附件/照片1.jpg" "/本次附件/照片2.png"
```

照片按文件内容 SHA-256 去重，同名不同内容分别保存，重复上传保留上传记录但墙上只显示一次。原文件不移动、不删；图片只校验与复制，不改像素。批量上传先校验全部图片，遇到无法解码的格式保留原件，说明尚未入库；若转换预览，需使用另存的副本，不能覆盖原件或把转换版冒充原始文件。参考样图、界面截图、生成成品不能误归为用户本人原照。

命令返回照片编号与持久路径。后续选照片可直接查看照片墙；照片数量增加时不要求用户重新上传旧照片。用户要求换一张或挑照片时，展示已有照片供其选择。

## 每次生成封面

设计内容和生成引擎沿用主 Skill。完成配置后执行：

```sh
python3 scripts/asset_library.py --content-dir "/当前内容文件夹" prepare "/本轮设计/config.json"
```

此命令将实际参考照入库，替换配置中的参考照路径、编号与输出位置，在资料库中建立唯一新轮次并调用原编译器；不调用生图、不更换模型。使用它返回的 `batch` 路径运行执行器；实际输出格式以文件内容为准。

执行器返回每张图片后立即保存：

```sh
python3 scripts/asset_library.py --content-dir "/当前内容文件夹" save-cover "/资料库/封面作品/本轮" "wall-27" "/执行器返回的图片.png"
```

如果执行器已将图片写入本轮计划的 `候选/` 路径，执行：

```sh
python3 scripts/asset_library.py --content-dir "/当前内容文件夹" sync "/资料库/封面作品/本轮"
```

每次成功输出都同步，不等全批完成；批量执行器仅在结束后返回时，在返回后立即同步，包括部分失败的批次。`sync` 只登记实际存在、可解码、提示词哈希与计划一致的图片；错误项会报告，不阻碍有效图片入库。生成记录包含标题、风格编号、参考照片编号及哈希、提示词及哈希、轮次、检查结果。保存成功会刷新照片墙、封面总墙；已打开的静态网页需刷新才能显示最新内容。

重复同步不会重复新增封面，也不会清除用户的选定状态。图像或提示词变化会另留版本；助手主动修改封面仍须重新 `prepare`，不覆盖旧轮。`save-cover` 拒绝用不同图片覆盖已有候选。照片、提示词与图像生成本身不因本流程改变。

完成视觉检查后更新本轮 `plan.json`，用本轮配置执行 `compile_batch.py --wall-only`，再 `sync` 更新总墙检查信息。用户明确选定后从 `封面索引.json` 找到对应封面编号，沿用同一 `--content-dir` 执行 `select 编号`；生成成功与已选定分开记录。

## 交付核验与中断恢复

只有命令成功返回、文件可读、索引含对应哈希、墙中图片链接存在时才说“已保存并更新”。优先交付资料库中的持久路径。失败时原附件与执行器结果保留，明确哪些已经保存、哪些待恢复；恢复目录后可重跑 `photos` / `save-cover` / `sync`。索引用同目录临时文件原子替换，库内修改串行加锁，避免中断写出半份 JSON。

历史照片库和旧封面目录保持原位。本次实际使用的旧参考照可以保存副本；不扫描、不搬迁整库。此流程由 Skill 处理本次上传和生图时触发，没有跨会话附件监听器，也没有后台定时任务。
