# 按照片与文字做设计判断

## 先看照片

记录背景是否有价值、哪里杂乱、光线与肤色、姿势和视线、可用留白。好看的原背景优先保留；局部杂乱优先通过裁切、局部遮挡或对比处理解决。抠图或背景替换只在本次模式与用户要求允许时采用。不要仅因样图使用纯色底就抠掉原背景。

## 组合设计语言

- 字体：从宽窄、字重、黑体或衬线、手写或展示字形、断行节奏选择；都要保持大字与中文可读性。不给所有内容套同一种粗黑字。
- 构图：根据照片和文字安排位置、疏密与叠层；脸和重点词互不遮挡，不规定上字下人或固定左右。
- 配色：参考原照和内容情绪，保证标题对比；人物原色不参与整体滤镜。
- 材质：纸张、拼贴、网点、清透或其他处理可用于背景和图形，不能把真人变成材质化人物。
- 装饰：由文字含义决定，可用隐喻，也可不加；不照搬样图的山、太阳、楼梯等道具。
- 背景：记录保留、局部处理或替换的理由；服从照片模式与本次授权。

这些维度供判断，不要求每张填满，不建立“某关键词必用某配色”的机械映射。三个候选应有构图、字形或视觉表达上的实质差别；无需为差异强造新人物场景。

## 当前57组风格目录

用户版风格墙只展示图片和名称；生成时读取本 skill 的 [style-catalog.json](style-catalog.json)，按 `label` 定位，使用 `id` 编译，并查看 `preview`。目录里的 `suitable` 只是用途示例，不限制其他主题。`layout` 提取字形、构图、材质或空间关系，不继承旧图中的具体文案、道具与坐标。不要把预览中的咖啡、时钟、花、书、灯泡等变成该风格的固定元素。

部分历史名称含“手绘”“涂鸦”“木刻”等：只能借鉴其平面节奏、印刷或背景材质，实际采用清晰印刷字与图形；不生成手绘人物、涂鸦装饰或笔刷字。真人始终自然彩色。07瑞士网格、21蓝晒和此前排除项未登记；45蓝图是构造线条设计，不是把人物变成蓝晒照片。

## 元素怎样服务内容

解释概念或方法时，先判断画面要表达哪个关系或变化，再选能够看见这个关系的元素。例如“零散灵感拼成作品”，纸片可共享同一图形并逐步组合成完整印刷品；不必添加咖啡、花和灯泡来表示创作。元素与标题只是在题材上相关，仍不足以说明它为什么出现在这里。

生活记录、情绪与观点可以用原照片、大字、留白或材质表达，不强制输入输出、机器装置或人物操作。照片里没有的动作不凭空制造。元素共同服务当前意思即可，不设固定数量，也不因删繁而把所有方向做成同一种纯色背景。

## 理解标题与澄清分歧

先读用户已经给出的正文、口播稿或本轮讨论，在现有 `topic` 中简记支持本次理解的内容；只有标题时注明依据仅为标题。`title_meaning` 写观众应理解的意思，以及本次需要避免的误读（如有），不新增固定问卷或字段。

同一句“别把忙碌当成进步”：若内容讲重复低效劳动，画面可强调原地循环与推进；若内容讲用琐事逃避重要任务，画面应强调琐事挤占一个被搁置的重点。先从已有内容判断；两种理解仍成立且会改变画面主旨时，问一句“这里更想讲低效重复，还是用琐事逃避重要的事？”，也接受用户另作解释。未得到回答前不擅自确定该画面。意思明确或差异只涉及装饰选择时直接设计，不例行索要确认。

## 从标题到整张画面

每次按以下顺序形成候选的 `visual_brief`，再把具体做法写入 `scene`。用户选择的风格提供设计语言，标题与内容决定本次表达；不把风格名映射成一套不变的道具和坐标。

1. `title_meaning`：结合本次内容，用一句话明确标题主要表达的关系、变化、冲突、选择或情绪。不改写用户已确认的标题，也不把抽象标题自行补成未经提供的结果。
2. `visual_expression`：明确观众能看见什么。例如碎片组成整体、密集重复与一个重点形成对比，或照片与排字留出呼吸空间。方法与概念可用变化关系；生活与情绪可用视线、留白、疏密或空间氛围。既有真人姿势不为创意而改造。
3. `overall_design`：说明这种表达怎样落实到所选风格的整图中。按实际需要决定相关元素、空间主次、材质、配色与字形排布；这些决定共同服务同一意思，不要求每个维度都加效果。原背景好看且适合时保留；人物原色、大字与无遮挡要求优先。

写完三项后，再检查关键元素的作用：它具体表现哪个关系或情绪？观众能从位置、形态、疏密或变化中看出来吗？若理由仅是“这个风格常用”或“与主题有关”，优先省去，或换成更贴切的表达。以一个主要关系或情绪组织画面；不要求所有装饰都承担象征含义，也不强制添加道具。将这些决定落实到 `scene`，检查两者没有矛盾。

下面是判断方法的正反例，不是固定模板或成图金标准：

| 内容意思 | 容易出现的偏差 | 更贴合的设计方向 |
|---|---|---|
| 零散灵感经过组织成为作品 | 纸片、书和灯泡只表示“创作” | 少量碎片与完整图形形成可见的组合关系 |
| 用琐事逃避重要任务 | 时钟和向上箭头变成“提高速度” | 周边密集的次要片段挤占一个未完成的重点，保持主次清楚 |
| 给自己留一点余地 | 加阶梯与奖杯，把松弛变成努力冲刺 | 用原照、排字间距与留白表达舒展，不强造任务和结果 |

例如同选轻拼贴：“零散灵感拼成作品”可用共享同一图形的碎片与完整印刷品；“别把忙碌当成进步”可用重复密集与清晰重点的关系；“给自己留一点余地”可用纸层、人物与文字之间的呼吸空间。示例解释关系，不是该标题必须使用的固定画面。换标题后重新设计，不只替换文字。

```json
{
  "title_meaning": "零散灵感经过组织，形成完整作品，而非只积攒素材",
  "visual_expression": "少量纸片共享同一图形，碎片与拼合后的整体形成清楚关系；人物保持原姿势",
  "overall_design": "轻拼贴中让组合关系成为主要图形，大字与纸层融入原照可用空间；色彩参考原照片，人物保持自然原色，不加无关创作道具"
}
```

生成后对照这三项看实际画面。装饰即使好看，如果不能帮助表达该标题的意思，应删减或替换；标题仍须是第一视觉层级。不要把所有封面都强行变成复杂事件、流程图或机器装置。

## 公开样例与用户偏好

57 张参考封面见包内 `assets/style-wall/index.html`，完整图像见 `assets/samples/`。目录中的 `preview` 相对 Skill 根目录解析。每次根据新用户的文字与照片重新设计；不继承敏敏的个人选款结果。样例含人物处理或文字遮挡缺陷时，只借鉴设计语言，不把缺陷当作要求。

## 检查与迭代

在原尺寸和约200px宽缩略图上检查：原文准确、主标题醒目、人物自然彩色、脸和重点词无遮挡、背景处理适当、装饰有意义。另看候选是否只是换色。发现问题后优先调整排字、对比或局部布局，不能靠缩小主标题解决；人物被变色或绘画化则该候选不通过。每次迭代重复保留约束。提示词编译通过不等于成图通过，须分别记录。

### 偏差定位与修正

在现有 `review` 中分开记录以下观察及需要的调整；尚未看到成图的项目标为待检查。先核对内容依据，再看画面，不能只用助手自己写的设计说明证明理解正确。

| 检查 | 观察依据 | 修正位置 |
|---|---|---|
| 意思是否准确 | 对照用户内容与 `title_meaning`：有无遗漏核心意思、增加未经提供的结果，或换成另一种观点 | 回到内容理解；存在实质分歧才澄清，随后调整受影响的设计 |
| 画面表达是否清楚 | 对照 `visual_expression` 和实际图像：预想关系是否可见，是否只剩一堆相关物件，是否产生相反含义 | 调整元素关系与 `scene`；表达方式不成立时换方案，不只重复重抽 |
| 视觉呈现是否合适 | 原尺寸及200px下查看标题、人物、主次与拥挤程度 | 意思与关系成立时局部修正排字、间距、对比或多余装饰，保留已确认部分 |

确认后的局部修改使用 `locked_design` 保存未获修改授权的属性。新场景为锁定标题让位，不为适配背景而擅自换字、缩字或改色；用户要求改变的属性才解除锁定。对照确认版检查实际图片，不把 JSON 或提示词中写了“保持”当成保真验证。
